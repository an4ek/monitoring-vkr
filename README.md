# Обработка событий мониторинга

ВКР, КемГУ, Институт цифры, 02.03.02, группа ФИТ-231.

Тема: «Информационная система обработки событий мониторинга для выявления сбоев и оповещения ответственных за ИТ-сервисы».

Система принимает события от систем мониторинга (Zabbix, Prometheus), по каталогу ресурсов и графу зависимостей определяет затронутые сервисы и первопричину сбоя, склеивает повторы в один инцидент, отправляет оповещения ответственным и подписчикам и показывает состояние сервисов на статус-страницах.

## Структура репозитория

| Папка | Что внутри | Кто ведёт |
|---|---|---|
| `backend/` | Сервер: Python, Django, Django REST Framework, Celery | Бэкенд |
| `frontend/` | Интерфейс: React, TypeScript | Фронтенд |
| `infra/` | docker-compose для инфраструктуры системы: PostgreSQL, RabbitMQ, Mailpit | Фронтенд |
| `stand/` | Тестовый стенд: Zabbix, Prometheus, наблюдаемые сервисы, Mattermost | Фронтенд |
| `docs/` | Диаграммы, схемы, черновики глав | Оба |

## Стек

- **Фронтенд:** React, TypeScript, React Router, TanStack Query
- **Бэкенд:** Python, Django, Django REST Framework, Celery
- **Брокер сообщений:** RabbitMQ
- **База данных:** PostgreSQL
- **Источники событий (стенд):** Zabbix, Prometheus + Alertmanager
- **Каналы оповещений:** Mattermost (на собственном сервере), электронная почта

## Как работаем с git

1. В ветку `main` напрямую не пишем.
2. Каждая задача делается в своей ветке: `feature/<коротко-что-делаем>`, например `feature/catalog-page` или `feature/zabbix-webhook`.
3. Готовую ветку вливаем в `main` через pull request. Вторая участница смотрит и подтверждает.
4. Перед началом работы обновляем `main`: `git checkout main && git pull`.
5. Сообщения коммитов пишем по-русски и по делу: «Добавлена страница каталога», «Приём вебхука от Zabbix».

## Запуск

Будет дописано по мере готовности частей:

- инфраструктура: `cd infra && docker compose up -d`
- стенд: `cd stand && docker compose up -d`
- бэкенд и обработчик событий: см. `backend/README.md`
- фронтенд: см. `frontend/README.md`
